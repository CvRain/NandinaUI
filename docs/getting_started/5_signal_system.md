# 用信号驱动界面更新

按钮已经能够响应点击，但如果每次状态变化都需要手动寻找控件并更新界面，程序很快就会变得难以维护。NandinaUI 的响应式系统把“状态是什么”和“界面如何展示状态”连接起来：`Signal` 保存可变值，`Computed` 从其他状态派生结果，`Effect` 在依赖变化时执行副作用，而绑定负责把最新值写入控件属性。

本章会把前面的按钮改造成一个简单计数器。计数值由当前页面的响应式作用域持有，按钮只负责修改它，文本则订阅派生出的显示内容。这个例子很小，却包含了状态驱动 UI 最关键的闭环，也为后续把状态放入 `NanStore` 或跨页面共享打下基础。

## 本章目标

- 使用 `ui.signal_value()` 创建由当前构建作用域管理的状态。
- 通过 `get()`、`peek()`、`set()` 与 `update()` 正确读写 `Signal`。
- 使用 `ui.computed()` 创建惰性计算的派生值。
- 将信号或计算值绑定到标签及可写视觉属性。
- 理解响应式依赖追踪和作用域生命周期。

## 建议覆盖的知识点

- `Graph`、`ReactiveScope` 与 `BuildContext` 的所有权关系。
- `get()` 会追踪依赖，而 `peek()` 不会追踪依赖。
- 相同值写入、派生值缓存和更新调度。
- `effect`、属性绑定与 `Label::bind_text()` 的适用场景。
- `batch` 如何把多次状态修改合并为一次响应式刷新。

> 建议本章只使用页面内局部状态；跨页面状态与 `NanStore` 可以在掌握 `app::Page` 后另设进阶章节。
