# PR #15 审核后续项

审核基线：`6a9d827`（`codex/all-development` → `main`）。以下是非阻断项；
处理时仍按 [开发流程](development_loop.md) 先定 API 与归属，再加会红的测试。

## 1. 错峰间隔累计溢出

`scene::AnimationGroup::stagger()` 只检查单个 `interval` 有限且非负，随后用
`float delay += interval` 生成各 clip 的启动时刻。三个步骤与足够大的有限间隔
（例如 `std::numeric_limits<float>::max()`）可使第三个时刻成为无穷大；它的
`ready(elapsed)` 永远不成立，Host 轨道也就无法自然结束。

- 修复：在生成所有启动时刻前验证累计时刻均有限；非法规格在取消已有轨道之前
  拒绝。作者入口与低层 `AnimationGroup::stagger()` 应保持一致的错误契约。
- 验收：分别从两个入口提交上述三步骤规格，断言 `std::invalid_argument`，
  已有动画轨道与值保持不变。去掉累计校验时，该测试必须失败。

## 2. 系统字体链接的检查与打开

`text::system_fonts` 有意允许用户字体目录中的符号链接，但目录后端当前先对路径
调用 `file_size()`，再另行打开文件。链接目标可在两次操作之间变化，因而大小
校验和实际读取可能针对不同文件。当前调用方是系统字体发现，不构成本 PR 的
合并阻断；若后续将该模式用于不可信资源，不能沿用这个保证。

- 修复：在目录后端基于同一已打开文件句柄获取大小并读取；保留系统字体允许
  链接、一般资源默认禁止链接的现有策略。
- 验收：链接目标变化时不得绕过大小限制或返回与声明大小不符的资源；普通
  系统字体链接仍可发现和读取。测试应覆盖读取与流式接口。
